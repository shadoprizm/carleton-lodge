# History Information Architecture

## Principle

Carleton Lodge's history should be **deep, but contained**.

Visitors who want current Lodge information should not need to navigate through historical content. Visitors who choose History should be rewarded with a richer archive.

## Global site

Keep the current global information architecture and navigation. `History` remains a normal peer link.

Suggested conceptual hierarchy:

- Home
- About / Lodge information
- Current officers / current Lodge content
- Calendar / events
- Membership / help / contact as currently implemented
- History
- Gallery / links / other existing functions

Do not make History the first or visually dominant item unless it already is.

## `/history` landing

Purpose: orientation, not full narrative.

Components:
- concise hero
- 2–3 paragraph overview
- 7–10 key dates
- story cards
- 1 authentic archival image if rights-cleared
- link to sources
